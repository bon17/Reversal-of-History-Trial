## 0. 한눈에 보기

- 중학교 2학년 역사 수업용 역전재판식 법정 추리 **웹 게임**이다. HTML, CSS, JavaScript로 만들었고 빌드 도구는 없다. `index.html`을 열면 바로 돌아간다.
- 게임 1(1~3화 + 기억 노트)과 게임 2(4~6화 + 반박문 쓰기)로 나뉜다.
- **1~6화 게임이 모두 들어갔다.** 대본과 게임 데이터가 일치한다 (`node tools/check_script.mjs --ep 1`~`6`).
- 6화 끝의 **반박문 쓰기(학생에게는 "친구에게 답장하기")** 화면도 들어갔다 (`game/js/rebuttal.js`).
- **1~6화 그림은 모두 들어갔다.** **소리 파일은 아직 하나도 없다** (4장).
- 6화와 반박문 쓰기는 **선생님이 아직 직접 플레이해서 확인하지 않았다.** 브라우저 자동 시험(`tools/playtest.mjs`)으로는 4~6화와 반박문 쓰기를 끝까지 해 보았다.

## 4. 소리(BGM) 넣기

### 이미 만들어져 있는 것
- 넣는 곳: `assets/audio/bgm/`, `assets/audio/se/` (지금은 비어 있음)
- 파일 이름 표: `docs/게임_실행_안내.md` 5장 (BGM 10종, 효과음 50여 종. 6화에서 효과음 8개가 늘었다)
- 코드 속 이름 표: `game/data/common.js`의 `DATA.소리`. 대본의 (낮게), (잔잔하게), (절정) 같은 꾸밈말은 같은 파일을 다른 음량으로 튼다 (`꾸밈음량` 표).
- 게임이 알아서 하는 것: BGM 반복 재생, "멈춤"/"없음" 처리, 🟥 피해 기록을 제시하면 음악이 멈추고 화면이 차분해짐, 🟩 선택 기록은 음악 멈춤과 초록빛
- 형식은 `.mp3`를 권장한다 (`.ogg`, `.wav`, `.m4a`도 된다). 클라우드플레어는 파일 하나가 25MB를 넘을 수 없다.
- HTML 한 파일 백업에도 소리를 넣을 수 있다. `assets/audio/`에 파일이 있으면 `tools/build_single_html.mjs`가 함께 넣고, 이미 만든 HTML에는 `tools/embed_audio.mjs`로 넣는다. 게임 1 파일은 이미 약 29.5MB라서 BGM을 넣으면 30MB를 넘는다 (`docs/인계문_BGM.md` 5장). 게임 2 파일(약 27.9MB)은 30MB를 넘으면 빌드 도구가 인물·배경 그림을 조금 더 압축해서 맞춘다 (실행 안내 1장).
- 브라우저 규칙 때문에 소리는 학생이 처음 화면에서 버튼을 한 번 누른 뒤부터 난다.

- 기억, 역전, 레테 세 곡이 절반이 넘으니 먼저 구한다. 기억 테마는 피해 증언 장면에 가장 많이 나오므로 가장 신중하게 고른다.
- "멈춤"과 "없음"은 50번 넘게 나온다.

### 곡을 고를 때 지킬 것
- 역전재판 원작 OST, 음성은 쓰지 않는다 (기획서 8장). 로열티 프리 음원이나 직접 녹음한 것만 쓴다 (기획서 9장).
- 6화 히틀러 장면에는 웅장한 음악을 쓰지 않는다 (기획서 6장 히틀러 연출 원칙).
- 곡마다 출처와 라이선스를 기록해 둔다. 출처 표기가 필요한 곡은 게임 안에도 표기한다.

### 곡 판별과 다듬기 (Claude 세션에서)
- ffmpeg가 있으면 길이, 형식, 앞뒤 무음, 음량을 잴 수 있다. `pip install librosa`를 더하면 템포(BPM), 장조/단조, 세기 변화도 볼 수 있다.
- 반복 재생할 때 끝과 처음이 자연스럽게 이어지는지 확인하고, 앞뒤 무음을 자르고, 곡끼리 음량을 맞춘다 (ffmpeg `loudnorm`).
- Claude는 소리를 직접 듣지 못하고 측정값으로 판단한다. 분위기는 선생님이 직접 들어 보고 최종 결정한다. 소리만으로 원작 OST인지 가려낼 수도 없으니 출처 링크와 라이선스 문구를 함께 받는다.

- `4~6화를 플레이해 보고 고칠 곳을 적었어. 하나씩 고치고 게임 2 HTML 파일을 만들어 줘.`
- `BGM 넣기. 내가 음악 파일을 주면 어느 테마에 맞는지 판별하고 다듬어서 assets/audio/bgm/ 에 넣어 줘.`
- `클라우드플레어 배포 설정을 도와줘. (기획서 13장)`

### 다른 계정에서 할 때 알아 둘 것
- 저장소가 공개라서 읽기와 받기는 어느 계정에서나 된다.
- **올리기(push)는 그 계정에 연결된 GitHub 계정이 이 저장소에 쓸 수 있어야 된다.** 올리기가 막히면 (1) 저장소 주인(`bon17`)이 Settings → Collaborators에서 그 GitHub 계정을 더하거나, (2) 세션이 만든 파일을 받아서 GitHub 웹에서 이 브랜치에 직접 올린다.
- 선생님의 claude.ai 아티팩트는 다른 계정에서 고칠 수 없다. 테스트용 게임은 HTML 파일로 받는다 (1장).

## 6. 작업 규칙 (지금까지 지켜 온 것)

- **대본이 기준이다.** 대본을 고치면 `node tools/check_script.mjs --ep N`으로 게임 데이터와 비교한다.
- 게임을 고친 뒤에는 `node tools/playtest.mjs --from 4 --to 6 --probe`로 브라우저에서 끝까지 해 본다 (Node.js와 Playwright가 필요하다). 찍은 화면은 `dist/playtest/`에 생긴다.
- 그림을 바꾸거나 더하면 `node tools/make_webp.mjs`로 WebP 복사본을 다시 만든다.
- 학생에게 올리는 사이트에는 `docs/`를 넣지 않는다. 대본에 모든 정답과 교사용 메모가 있다 (기획서 13장).
- 시험할 때 선생님의 구글 시트(`DATA.설정.GAS주소`)로 답을 보내지 않는다 (자동 시험은 가로챈다).
- 문서와 커밋 메시지는 쉬운 한국어로 쓴다.
- 피해자, 왜곡 주장, 혐오를 다루는 금지선은 기획서 8장을 따른다.
